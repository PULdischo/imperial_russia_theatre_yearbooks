Known open issue (docs/eval/known_issues.md #68, unresolved as of
2026-09-01): this prompt has been observed to occasionally split ONE
printed row -- specifically a benefit-performance entry with no receipts
figure of its own -- into two output rows instead of one, throwing off
every row's position after that point. A prompt rewrite explicitly
telling the model not to do this was tried and made things WORSE (it
started dropping dark rows and fabricating duplicate receipts instead),
so that fix is not included here. If a page's row count from this prompt
doesn't match the date-only extraction's row count for the same page,
that mismatch itself is a real signal worth checking -- but as of the
`session` field above, it is no longer automatically treated as this
theater's read being unreliable: the caller now aligns rows by calendar
day and session label instead of raw position, so a day where this
theater genuinely performs once while another theater performs twice is
expected and correctly handled, not an error.
