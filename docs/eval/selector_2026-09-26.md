# The selector — choosing among readings several views produced

2026-09-26. `pipeline/select_reading.py`. No new API calls; built on the
253 calls already made for the multi-view test
(`docs/eval/multiview_merge_2026-09-26.md`).

**Goal it serves** (RG, 2026-09-26): a diplomatic transcription without many
human hours. Every error the selector fixes is an error nobody reads.

## Result, 11 gold pages, 2,209 body words

| | misread | accuracy |
|---|---|---|
| single full-page pass | 56 | 97.46% |
| majority vote over 6 views | 42 | 98.10% |
| **selector over 6 views** | **24** | **98.91%** |
| selector + `-аго` opt-in | 23 | 98.96% |
| oracle ceiling (6 views) | 16 | 99.28% |

The selector fixes **18** readings majority got wrong and breaks **0**. It
closes 30 of the 40 errors that were recoverable at all, taking roughly
**57% of all errors out of the corpus with no human involvement**:
~5,200 -> ~2,230 across 1,024 pages.

## Design: rejection, not preference

The safety property is `orthography.py`'s, and it is the whole design: **a
selector may only choose among readings a view actually produced.** It never
invents a form and never corrects the page towards a norm — pre-reform
orthography is unstable (RG, 2026-09-25), so almost every rule REJECTS
something impossible rather than preferring something expected.

In order:

1. a dropped word never beats a read one
2. multi-token candidates lose to single-token ones (alignment debris from a
   view that merged lines)
3. a token mixing Cyrillic and Latin loses to a clean one — pure-Latin
   French titles are untouched
4. **end-of-line hyphen kept** when candidates differ only by it
5. `judge_hard_soft` (ъ/ь)
6. `judge_i_vs_i` (і/и) — **one direction only**, see below
7. majority; and when nothing wins more than one vote the selector says
   `REVIEW:` instead of pretending

Rules 4 and the opt-in `-аго` are the two that encode a preference. Both are
marked in the source as encoding a known direction of MODEL bias (it drops
printed hyphens; it modernises `-аго` to `-ого`), not a claim about the
print. `-аго` is **off by default** because it does assert a norm.

## і/и had to be restricted, and that is the instability point again

Applied in both directions the і/и judge scored **0 fixes and 2 breaks**,
overwriting `Тихоміровъ` with `Тихомировъ` twice. The "і before a vowel or
й" direction holds; the converse ("и everywhere else") does not, because the
corpus prints **both** `Тихоміровъ` and `Тихомировъ` — the second is on the
page RG triaged on 2026-09-25. The judge is now accepted only when its
answer actually places і before a vowel or й.

This is the third time the same shape of mistake has been caught: the
reverted `-арь/-ярь` suffix rule, the withdrawn fita error-rate, and now
this. See [[pre-reform-orthography-is-unstable]].

## Self-test

`uv run python pipeline/select_reading.py` — 13 cases built from RG's own
rulings (Легатъ, Аслинъ, юбиляръ, пожаръ, Тихоміровъ) plus the gold set,
including a `_MUST_FLAG` list of cases the selector must NOT decide
silently. A rule change that breaks any of these is wrong. Same gate
`orthography.py` carries, and for the same reason: the `-арь/-ярь` change
would have been caught by it.

## The human queue that is left

24 residual errors on 11 pages; 9 of them are still recoverable (some view
read them correctly), 15 are read wrongly by every view.

| queue rule | sites | errors caught | yield |
|---|---|---|---|
| selector says `REVIEW:` (no majority) | 0 | 0/24 | — |
| orthography says CHECK THE SCAN | 30 | 3/24 | 0.10 |
| any view disagrees (exhaustive) | 180 | 16/24 | 0.09 |

Scaled to 1,024 pages: the CHECK-THE-SCAN queue is ~2,800 decisions for
~280 errors; the exhaustive queue is ~16,800 decisions for ~1,500.

The `REVIEW:` rule finds nothing here because with six views there is almost
always a majority. It is not dead code — it fired on the real
`юбилияръ/юбиляръ/юбилярь` triage case, which had only three views.

The CHECK-THE-SCAN queue is only 10% precise, but it is the only rule that
reaches errors where **all six views agree on the same wrong reading**
(`говоритъ` read as `говорить` by every view). The disagreement queue cannot
see that class by construction.

## Residual classes worth a look before more rules

Of the 24 left, three are not really reading errors:

- **`l’Etoile` vs `l'Etoile`, `d’épice` vs `d'épice`** — curly versus
  straight apostrophe. A codepoint convention question, not a misreading.
  Settling it is 2 of 24 for free.
- **`Людмилѣ»(17-го`** — RG already ruled there is no space before `(17-го`;
  every view inserts one.
- **`Nèbuleuses` -> `Nébuleuses`, `Merveileuses` -> `Merveilleuses`** — the
  model silently repairing the printing's own errors, which gold preserves.

## Not yet wired in

`select_reading.py` is a module with a self-test and a measurement. Wiring
it into the pipeline needs a multi-view run to exist for the corpus, which
is a decision for the priorities conversation, not a follow-on task.
